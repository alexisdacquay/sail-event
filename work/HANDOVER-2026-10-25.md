## What the product is

Sail-event finds events matching a user's free-text criteria ("AI events in London next
week"): web search (Tavily, 20 results with full page text) → LLM extracts events from
every page → code filters (complete, future, not duplicate) → LLM judge scores each event
0-100 against the criteria → thresholds triage (accept / review / reject) → per-user ICS
calendar feed. React/Vite frontend, FastAPI backend, SQLite dev / Postgres prod, on Render.

## How a turn goes

1. Owner names the item. 2. PM agent grooms it into an issue with acceptance criteria
(label `mvp` or `post-mvp`). 3. Engineer agent (Opus) implements in a worktree, red test
first, measures before/after with the runner, opens a PR, comments on the issue.
4. QA agent posts PASS/FAIL on the issue. 5. You report to the owner: what the PR is in
words, numbers, verdict. 6. On their word: merge (squash), close the issue, one line in
`work/STATE.md`, push. 7. Nothing to prod unless they say so.
